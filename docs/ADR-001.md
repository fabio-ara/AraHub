# ADR 001 — Monólito modular e contratos portados

Decisão: Deno/TypeScript com Postgres e SQL transacional compatível com Supabase. Módulos de domínio, adapters, HTTP/MCP e interface pequena. Runtime local comprova domínio/SQL; ambiente Supabase hospedado continua sujeito a gate próprio.

Motivo: evitar outra linguagem de runtime hospedado e serviços pagos; preservar a semântica auditada do projeto Moodle. A origem técnica não possui LICENSE rastreada no snapshot auditado; não copiar implementação nem presumir relicenciamento. Nova implementação independente baseada em APIs e contratos.

Prova local usa Postgres em container exclusivo. A compatibilidade de `auth.uid()` local será explicitamente identificada como fixture de identidade; OAuth real é validado somente no ambiente autorizado. Tokens do modelo nunca definem `owner_id`; identidade vem do verificador confiável.

Consequências: dependências exatas e lockfile, RLS + FKs compostas, grants mínimos. Busca textual sem API de IA/embeddings. Transporte MCP por SDK oficial, sem servidor OAuth artesanal.
